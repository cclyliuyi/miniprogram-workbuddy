# 洞见文章制作与发布工作流

对应专用技能：`insights-article`，本机位置为 `C:/Users/Administrator/.codex/skills/insights-article/SKILL.md`。

## 以后怎么交稿

直接发原文、Markdown、Word、HTML 或本地文件路径。没有排版、没有图片也可以。可附上读者、想保留的语气和发布日期；无特殊要求就按默认规则推进。

- **“按洞见流程处理这篇原稿。”** 整理、排版、按需配图、构建并交付可预览成稿。
- **“按洞见流程处理并发布到洞见。”** 在成稿基础上，完成备份、云端上传和开发工具真实验收。
- **“只排版，不改文字／不要配图／先不发布。”** 指定范围优先于默认规则。

## 固定流程

| 环节 | 要做的事 | 完成依据 |
| --- | --- | --- |
| 接稿 | 保存原稿，明确主线与关键论点，必要时核对事实 | 保留立场，不增编经历、数据或结论 |
| 编辑 | 分段，提炼标题、导语、章节和小节，整理列表或步骤 | 可以扫读，论证强度和原意不变 |
| 重点排版 | 区分普通加粗、金色概念、底纹结论；按需要加入卡片、旁注、引用、编号 | 不把整篇都加粗，标识对应实际内容 |
| 配图 | 检查素材，制作适合的封面或解释性插图 | 风格统一，手机上可读，不凑数或伪造数据 |
| 制作预览 | 生成兼容 HTML、JSON 和图片，检查是否丢失结构 | 内容核对和编译通过，移动端预览可读 |
| 按授权发布 | 合并远端最新目录，备份，依次上传图片、正文、清单 | 其他文章保留，清单最后上传，失败时停止推进 |
| 实际验收 | 从开发工具正常入口重新打开，检查版本和显示 | 层级、重点、图片、目录实际生效，保存真实截图 |

## 默认风格和输出

沿用米白纸色、靛蓝标题和金色重点。长文可分章节，短文简洁呈现。一般重点、关键词和核心结论使用不同强度的标识；概念、步骤、限制条件使用不同组件。

配图数量按内容决定，长文通常是一张封面加少量关键插图，不强制每章有图。图注说明必要的示意性质；技术图和数据图保证准确、可核对。

默认以图形解释内容，图内只放少量简短的大字标签，避免密集小字、长句和整段说明。技术细节放在可随手机排版缩放的正文与图注里。按约 320px 宽检查，不能依赖点开放大阅读。长文在合适的段落之间穿插图片，不集中堆在开头。

每篇工作文件放在 `tools/insights/drafts/<文章ID>/`：原稿副本、`article.html` 和实际素材。构建产物在 `tools/insights/dist/`。交付时说明成稿位置、预览方式、重要编辑说明和发布状态；发布后记录备份及云端路径。

## 发布边界与验收

处理原稿不会自动公开发布；明确要求发布后，在已有授权内直接完成，不逐项重复确认。这套流程不自动提交或发布小程序代码版本。

浏览器截图只代表浏览器预览。上传日志只证明接口成功。发布验收必须检查正常打开后小程序实际读取的数据及显示效果，不能用临时替换页面数据代替。

正文和清单请求已有 `_insights` 参数，避免覆盖同名 JSON 后继续读旧缓存。新增文章继续使用当前阅读器支持的结构；引入新组件或交互才涉及代码升级。

构建、上传命令及工具限制见 [文章发布指南](README.md)。`upload.js` 不会自动合并远端清单或备份，执行前先完成这两项；`make-console-sync.js` 只用于已有文章且插图未变的更新，不用于新文。
